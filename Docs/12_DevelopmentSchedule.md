# 12. 開発スケジュール

## 1. 前提

- 週25～30時間
- 6カ月～1年
- 転職活動と並行
- 最初の企業提出は開発開始から3カ月後
- 途中状態でも提出可能にする
- 3カ月時点ではゲーム全体より、ボス1体との戦闘品質を優先する

## 2. 0～1カ月

### 目的

戦闘基盤の成立を確認する。

### 作業

- プロジェクト初期設定
- Git / Git LFS
- コーディング規約
- Enhanced Input
- PlayerState ASC
- AttributeSet
- Gameplay Tag
- 移動プロトタイプ
- Mover段階検証開始
- 剣通常攻撃
- スタミナ
- 入力バッファ
- ロックオン
- テストマップ

### 完了条件

- 剣で敵ダミーを攻撃できる
- 攻撃と回避でスタミナを消費する
- ゲームパッドとキーボード・マウスで操作できる
- Mover継続可否を判断できる材料がある

## 3. 2カ月目

### 作業

- 剣4段コンボ
- 強攻撃分岐
- 空中攻撃
- ジャスト回避
- パリィ
- 体勢値
- ダウン
- 致命攻撃
- 近接敵
- 遠距離敵
- Behavior Tree
- 集団戦管理
- チェックポイント
- 回復アイテム

### 完了条件

- 通常戦の基本ループが成立する
- ジャスト回避とパリィから反撃できる
- 近接2体の攻撃枠が機能する

## 4. 3カ月目

### 作業

- ボス1体
- StateTree
- C++攻撃評価
- Phase1 / Phase2
- 行動履歴
- AIデバッグ表示
- 導入テキスト
- チュートリアル
- セーブ
- 死亡素材
- 基本UI
- パフォーマンス初回計測
- 技術資料初版
- プレイ動画

### 提出版完了条件

- タイトルからボス撃破まで進行可能
- ボス1体と高品質な1対1戦闘ができる
- 60fps目標を確認できる
- 実行ビルドを提出できる
- READMEと主要設計資料が完成している

- 最適化
